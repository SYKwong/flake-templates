The `c` template scaffolds a self-contained C playground with unit testing, mocking, standalone compilation, and LSP integration.

## Toolchain & Dependencies

Provided declaratively via `c/flake.nix` across `x86_64-linux`, `aarch64-linux`, and `aarch64-darwin`:

- **Ceedling `1.2.2`** (Unity `2.7.2`, CMock `2.7.2`, CException `1.3.5`): Packaged via `pkgs.bundlerEnv` from `Gemfile`, `Gemfile.lock`, and `gemset.nix` rather than `pkgs.ceedling`.
- **`gcc` & `gdb`**: Compiler and debugger.
- **`just`**: Task runner wrapping common test, build, and clean commands.

## Project Layout

```text
.
├── .clangd          # Points clangd to build/artifacts/compile_commands.json
├── .envrc           # Runs `use flake` for direnv
├── Gemfile          # Ruby gem declaration (ceedling)
├── Gemfile.lock     # Pinned Ruby gem versions
├── gemset.nix       # Nix-hashed gem definitions generated by bundix
├── flake.nix        # System-agnostic devShell
├── flake.lock       # Pinned nixpkgs input
├── justfile         # Task runner recipes
├── project.yml      # Ceedling & CMock configuration
├── include/
│   └── example.h
├── src/
│   ├── example.c
│   └── main.c
└── test/
    └── test_example.c
```

## Task Runner (`justfile`)

| Command | Action |
| :--- | :--- |
| `just` | Lists available recipes |
| `just test` | Runs `ceedling test:all` and updates `compile_commands.json` |
| `just test <target>` | Runs a single test suite (e.g. `just test test_example.c` or `just test example`) |
| `just build` | Runs `just test` (must pass), then compiles `src/*.c` with `-Wall -Wextra -g -Iinclude` into `build/main` |
| `just run` | Runs `just build`, then executes `./build/main` |
| `just clean` | Runs `ceedling clobber` and removes `build/` |

## Editor & LSP Setup (`clangd`)

`project.yml` enables the `compile_commands_json_db` plugin, and `.clangd` sets:

```yaml
CompileFlags:
  CompilationDatabase: build/artifacts
```

Run `just test` once after creating a project so `build/artifacts/compile_commands.json` is generated for `clangd`.

## Updating Ceedling Gems

If you ever want to bump `ceedling` or add Ruby gems inside a project:

```bash
nix shell nixpkgs#ruby nixpkgs#bundler nixpkgs#bundix --command bash -c "bundle lock --update && bundix"
```

## Quirks

- **macOS debugging**: `gdb` is included in `devShell` (useful for remote/embedded targets), but attaching it to local macOS processes requires code-signing entitlements; use `lldb` for local debugging on macOS.
- **Supported systems**: Targets `x86_64-linux`, `aarch64-linux`, and `aarch64-darwin` (`x86_64-darwin` was dropped in `nixpkgs` 26.11).
- **`clangd` index**: `build/artifacts/compile_commands.json` is generated on demand when running `just test`.
